Linux 无 root 权限运行 CrashCore，并让命令行走代理

一份精简流程：下载 CrashCore、准备 country.mmdb、上传本地改好的机场订阅、启动核心、设置命令行代理，并用代理安装 Codex CLI。

示例端口mixed-port: 7893
核心原则本地改好 YAML，再上传服务器
目录 适用场景 1. 创建工作目录 2. 下载 CrashCore 3. 下载 country.mmdb 4. 准备 scnet.yaml 5. 本地提前改好端口 6. 手动启动测试 7. 设置当前终端代理 8. 用代理安装 Codex CLI 9. 常用命令汇总 10. 最小完整流程 11. 核心记住

适用场景

  • 普通 Linux 用户，没有 root 权限。
  • 想在服务器上运行 CrashCore / Mihomo。
  • 想让 curl、git、npm、安装脚本等命令行工具走代理。
本文路径统一使用 /public/home/freemax/clash，端口示例使用 7893。如果你的端口不是 7893，把文中的 7893 换成你的 mixed-port 端口即可。

1. 创建工作目录

bash
mkdir -p /public/home/freemax/clash
cd /public/home/freemax/clash

2. 下载 CrashCore 二进制文件

服务器是 Linux x86_64，所以使用 clash-linux-amd64.tar.gz。

GitHub 页面地址是：

text
https://github.com/juewuy/ShellCrash/blob/update/bin/meta/clash-linux-amd64.tar.gz

但 curl 不能直接下载 blob 页面，要用 raw 地址：

bash
curl -L -o CrashCore.tar.gz \
  https://raw.githubusercontent.com/juewuy/ShellCrash/update/bin/meta/clash-linux-amd64.tar.gz

如果 GitHub raw 下载慢，可以用 CDN：

bash
curl -L -o CrashCore.tar.gz \
  https://testingcf.jsdelivr.net/gh/juewuy/ShellCrash@update/bin/meta/clash-linux-amd64.tar.gz

解压、赋权、检查：

bash
tar -zxf CrashCore.tar.gz
chmod +x CrashCore
ls -lh CrashCore

如果不知道服务器架构，先看：

bash
uname -m
常见对应关系：
x86_64 → clash-linux-amd64.tar.gz
aarch64 → clash-linux-arm64.tar.gz
armv7l → clash-linux-armv7.tar.gz

3. 下载 country.mmdb

CrashCore / Mihomo 启动时可能会提示：

log
Can't find MMDB, start download

如果服务器下载慢，可以提前手动下载 country.mmdb。

推荐地址：

bash
curl -L -o country.mmdb \
  https://testingcf.jsdelivr.net/gh/MetaCubeX/meta-rules-dat@release/country.mmdb

或者 GitHub release 地址：

bash
curl -L -o country.mmdb \
  https://github.com/MetaCubeX/meta-rules-dat/releases/download/latest/country.mmdb

检查：

bash
ls -lh country.mmdb

4. 准备 scnet.yaml

最简单的方式：

  1. 在本地电脑下载机场 Clash / Mihomo 订阅。
  2. 在本地把 mixed-port 改好。
  3. 把配置文件命名为 scnet.yaml。
  4. 再上传到服务器。

上传：

bash
scp scnet.yaml freemax@login07:/public/home/freemax/clash/

5. 本地提前改好端口

在本地编辑 scnet.yaml，确认里面有：

yaml
mixed-port: 7893

建议也加上：

yaml
ipv6: false

控制端口可以保留，例如：

yaml
external-controller: '127.0.0.1:9091'
最终上传到服务器的配置文件里，至少应该确认有：mixed-port: 7893 和 ipv6: false。

6. 手动启动测试

bash
/public/home/freemax/clash/CrashCore \
  -d /public/home/freemax/clash \
  -f /public/home/freemax/clash/scnet.yaml

看到类似：

log
Initial configuration complete

说明配置加载成功。

如果看到 The `global-client-fingerprint` configuration is deprecated，这是警告，不影响使用。
如果看到 bind: address already in use，说明端口被占用了，需要换一个 mixed-port。

7. 设置当前终端代理

如果只想让当前终端走代理：

bash
export http_proxy=http://127.0.0.1:7893
export https_proxy=http://127.0.0.1:7893
export all_proxy=http://127.0.0.1:7893

测试：

bash
curl ipinfo.io

取消代理：

bash
unset http_proxy https_proxy all_proxy
curl -x http://127.0.0.1:7893 ... 只对当前这条 curl 生效；export http_proxy=... 会让当前终端里的后续命令也走代理。

8. 用代理安装 Codex CLI

不要只写：

bash
curl -x http://127.0.0.1:7893 -fsSL https://chatgpt.com/codex/install.sh | sh

这种写法只代理了第一层 curl，安装脚本内部继续下载时，可能不会走代理。

推荐先设置环境变量：

bash
export http_proxy=http://127.0.0.1:7893
export https_proxy=http://127.0.0.1:7893
export all_proxy=http://127.0.0.1:7893

然后下载脚本并执行：

bash
curl -fsSL https://chatgpt.com/codex/install.sh -o install.sh
sh install.sh

如果下载中途出现 curl: (35) Encountered end of file，可以试试强制 HTTP/1.1：

bash
curl --http1.1 -fsSL https://chatgpt.com/codex/install.sh -o install.sh
sh install.sh

安装完成后，如果不想继续让终端走代理：

bash
unset http_proxy https_proxy all_proxy

10. 最小完整流程

bash · 带中文注释
# 创建 CrashCore 工作目录
mkdir -p /public/home/freemax/clash
cd /public/home/freemax/clash

# 下载 CrashCore 二进制压缩包
# 这是 ShellCrash update 分支里的 Linux x86_64 内核包
curl -L -o CrashCore.tar.gz \
  https://testingcf.jsdelivr.net/gh/juewuy/ShellCrash@update/bin/meta/clash-linux-amd64.tar.gz

# 解压 CrashCore
tar -zxf CrashCore.tar.gz

# 给 CrashCore 添加执行权限
chmod +x CrashCore

# 下载 country.mmdb
# 避免 CrashCore 启动时自己下载 MMDB 卡住
curl -L -o country.mmdb \
  https://testingcf.jsdelivr.net/gh/MetaCubeX/meta-rules-dat@release/country.mmdb

# 准备 scnet.yaml
# 推荐在本地电脑提前把机场订阅改好：
# 1. mixed-port: 7893
# 2. ipv6: false
# 3. 保存为 scnet.yaml
# 然后上传到 /public/home/freemax/clash/
#
# 示例上传命令需要在本地电脑执行：
# scp scnet.yaml freemax@login07:/public/home/freemax/clash/

# 检查当前目录文件
# 至少应该有 CrashCore、country.mmdb、scnet.yaml
ls -lh

# 前台启动 CrashCore
# -d 指定工作目录
# -f 指定配置文件
/public/home/freemax/clash/CrashCore \
  -d /public/home/freemax/clash \
  -f /public/home/freemax/clash/scnet.yaml

# 如果启动成功，会看到 Initial configuration complete
# 如果想停止，可以另开一个终端执行：
# pkill -f CrashCore

# 设置当前终端代理
# 端口要和 scnet.yaml 里的 mixed-port 保持一致
export http_proxy=http://127.0.0.1:7893
export https_proxy=http://127.0.0.1:7893
export all_proxy=http://127.0.0.1:7893

# 测试代理是否可用
curl ipinfo.io

# 用代理安装 Codex CLI
# 先 export，再运行安装脚本，这样脚本内部的下载也会走代理
curl -fsSL https://chatgpt.com/codex/install.sh -o install.sh
sh install.sh

# 安装完成后，如果不需要代理，可以取消环境变量
unset http_proxy https_proxy all_proxy

11. 核心记住

  • scnet.yaml 在本地改好再上传，最省事。
  • CrashCore 端口看 mixed-port。
  • 命令行代理用 export http_proxy / https_proxy / all_proxy。
  • curl -x 只代理当前 curl，不一定代理脚本内部的二次下载。
  • 安装 Codex 这类脚本时，优先用 export 方式。
